**ASSET TYPE DETECTION:**
- Token Metadata: Account owner is SPL_TOKEN_PROGRAM_ID
- Nifty Asset: Account owner is ASSET_PROGRAM_ID from @nifty-oss/asset
- MPL Core: Account owner is MPL_CORE_PROGRAM_ID from @metaplex-foundation/mpl-core

**KEY IMPORTS:**
- @metaplex-foundation/mpl-token-metadata: lockV1, unlockV1, delegateUtilityV1, revokeUtilityV1, transferV1
- @nifty-oss/asset: lock, unlock, approve, revoke, transfer, DelegateRole, ASSET_PROGRAM_ID
- @metaplex-foundation/mpl-core: addPluginV1, removePluginV1, createPlugin, PluginType, MPL_CORE_PROGRAM_ID

**CONSTRAINT:**
- Must use @solana/kit for all Solana operations - NO @solana/web3.js

**JOTAI SET TYPING:**
- When creating atoms with Set, use explicit generic: `atom<Set<string>>(new Set<string>())`
- `new Set()` alone infers `Set<unknown>` which causes type errors

**VAULT DETECTION:**
- NFT is vaulted when: `nft.frozen === true && nft.delegate !== null`
- Detection runs via DataFetcher component in layout/index.tsx when nftsAtom changes
- detectVaultedNftsAtom in vault.ts scans nftsAtom and populates vaultedMintsSetAtom

**VAULT DIALOG PATTERNS:**
- VaultDialog component at apps/web/src/components/vault/VaultDialog.tsx
- Uses button-based selection instead of RadioGroup for freeze type options
- Linked wallets feature not yet implemented in new app — secure freeze disabled by default
- NFT preview shows first 5 images with +X more indicator

**VAULT TRANSACTION EXECUTION:**
- prepareAndSendTransaction from lib/transaction.ts handles simulation, CU limit, priority fees, signing, and confirmation
- useTransactionSigner hook provides signer with capabilities.canSign check
- addVaultedMintsAtom action atom adds mints to vaultedMintsSetAtom after successful transaction
- Use Promise.all to build instructions for multiple NFTs in parallel, then flatten

**UNVAULT DIALOG PATTERNS:**
- UnvaultDialog component at apps/web/src/components/vault/UnvaultDialog.tsx
- Shows per-NFT authority status with teal checkmark (has authority) or amber warning (no authority)
- Only processes NFTs where connected wallet === delegate
- NFTs without authority shown but disabled/dimmed
- removeVaultedMintsAtom action atom removes mints from vaultedMintsSetAtom after successful transaction

**RECOVER DIALOG PATTERNS:**
- RecoverDialog component at apps/web/src/components/vault/RecoverDialog.tsx
- Requires linked wallets feature to select destination wallet (currently empty array placeholder)
- Uses amber color scheme (bg-amber-600, hover:bg-amber-700) for destructive action
- ArrowRightLeft icon from lucide-react for recover action
- Same authority checking pattern as UnvaultDialog
- buildRecoverInstructions in vault-transactions.ts handles unlock + transfer + closeAccount

**RECOVER TRANSACTION PATTERNS:**
- buildRecoverInstructions accepts: nft, owner, delegate, destination, payer
- Token Metadata (pNFT/regular): unlock → transfer → closeAccount (to reclaim rent to destination)
- Nifty Assets: unlock → transfer
- MPL Core: removePluginV1 → transferV1
- Uses getCloseAccountInstruction from @solana-program/token for closing source ATA
- For pNFTs: need both source and destination token records

**VAULT PAGE PATTERNS:**
- VaultPage at apps/web/src/routes/vault.tsx
- Uses vaultedNftsAtom from vault store for data
- Selection mode via isSelectModeAtom, selectedMintsAtom, toggleSelectModeAtom, clearSelectionAtom
- Filter selectedMints through vaultedNfts to get selectedNfts for dialogs
- Layout size toggle follows MembershipPage pattern
- Teal-400 color for vault-themed UI elements
- Select/Cancel toggle button for selection mode
- Shows count badge (e.g., "12 NFTs Protected") next to title
