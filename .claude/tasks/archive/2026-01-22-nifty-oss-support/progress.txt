## Codebase Patterns
- Run fetch-idls from the solana-programs directory: `cd packages/solana-programs && pnpm fetch-idls`
- IDL_SOURCES object in fetch-idls.ts maps short names (e.g., "asset") to raw GitHub URLs
- IDLs are saved to `packages/solana-programs/idls/` with the key name + .json extension
- **Incomplete IDLs**: nifty-oss asset IDL is missing type definitions (Standard, DelegateRole, ExtensionType). Use patchAssetIdl() in fetch-idls.ts to add them.
- **Stake SDK export conflicts**: When program name matches instruction name, fix with explicit exports and type aliases in generated/stake/index.ts and programs/stake.ts
- Import asset SDK as: `import { asset } from "@biblio/solana-programs"` then access `asset.Standard`, `asset.ExtensionType`, etc.
- **Nifty asset decoding**: Codama only generates instructions for nifty-oss, NOT account decoders. Use manual decoder in `apps/api/src/services/nifty.ts`.
- **Nifty asset layout**: 168-byte base (discriminator:1, state:1, standard:1, mutable:1, owner:32, group:32, authority:32, delegate:33, name:35) + variable extensions
- **@solana/kit ReadonlyUint8Array**: Use `new Uint8Array(rawData)` to convert ReadonlyUint8Array from getBase64Encoder().encode() for manual decoding
- **TokenStandard types**: Both API (das.ts) and frontend (stores/nfts.ts) have TokenStandard types - must keep in sync. Nifty assets use "Nifty" string value.
- **Merging nifty collections**: When adding nifty collections to DAS collections, check if collection already exists and increment count; otherwise add new entry.

- **NftCard is inline in nft-grid.tsx**: The NftCard component is defined inside nft-grid.tsx, not in a separate nft-card.tsx file.
- **Nifty badge positioning**: Uses bottom-left like Staked badge, hidden when NFT is staked (isStaked check) to avoid overlap. Uses violet-500 for distinction from Staked badge (primary color).
- **Nifty constants location**: NIFTY_PROGRAM_ID and DANDIES_NIFTY_COLLECTION are in apps/web/src/hooks/use-staking.ts
- **StakeNifty accounts**: staker, collection, nftRecord?, stakeRecord, programConfig, asset, nftAuthority, signer, feesWallet, systemProgram (auto), niftyProgram
- **Nifty staking vs Core**: Nifty staking doesn't need assetCollection account (collection is passed separately), uses niftyProgram instead of coreProgram
- **UnstakeNifty accounts**: Same as UnstakeCore but uses niftyProgram instead of coreProgram. tokenProgram and systemProgram default automatically.
- **NFT type fields**: tokenStandard is string "Nifty" (not number), collectionId is string (use nft.collectionId not nft.collection)
- **Stake filter logic is in AvailableToStakeGrid.tsx**: Not in stake.tsx - the filtering is in the grid component
- **Stake/Unstake handlers are in dialog components**: StakeDialog.tsx, BulkStakeDialog.tsx, UnstakeDialog.tsx, BulkUnstakeDialog.tsx - not in stake.tsx
- **pNFT instruction names**: buildStakeInstructions and buildUnstakeInstructions (not Core variants - those are for Metaplex Core)
